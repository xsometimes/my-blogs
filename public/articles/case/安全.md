2. 内容安全政策（CSP）
服务器通过 Content-Security-Policy 响应头告诉浏览器：“只允许加载来自**这些域名**的脚本、图片、样式表等资源”。

|指令	|作用	|示例|
|-------------------------|--------------|--------------|
|default-src|	默认资源白名单（适用于未单独指定的资源类型）。	|default-src 'self'：只允许加载同源资源。|
|script-src|	允许加载的 JavaScript 来源。	|script-src'self' URL_ADDRESS|script-src|	允许加载的 JavaScript 来源。	|script-src'self' https://cdn.example.com：允许加载同源和指定 CDN 的脚本。|
|style-src|	允许加载的 CSS 来源。	|style-src'self' 'unsafe-inline'：允许同源 CSS 和内联样式（需谨慎使用 unsafe-inline）。|
|img-src|	允许加载的图片来源。	|img-src *：允许所有来源的图片（不推荐，建议限制具体域名）。|

|connect-src|	允许的 AJAX/Fetch 请求目标。	|connect-src'self' URL_ADDRESS|connect-src|	允许的 AJAX/Fetch 请求目标。	|connect-src'self' https://api.example.com：只允许向同源和指定 API 发送请求。|
|frame-ancestors|	允许嵌入当前页面的父页面来源（防点击劫持）。	|frame-ancestors 'none'：禁止被任何页面嵌入（适用于敏感页面）。|

3. CSRF Cross-Site Request Forgery（跨站请求伪造）。


|攻击类型|	英文全称|	核心原理	|防范措施|
|------------|-------------|--------------|--------------|
|XSS	|Cross-Site Scripting	|注入恶意 JS 代码获取用户信息	|HttpOnly Cookie、输入过滤、CSP、输出转义|
CSRF|	Cross-Site Request Forgery	|利用浏览器自动携带 Cookie 伪造请求	|SameSite Cookie、验证 Referer/Origin、CSRF Token|
CSP	|Content-Security-Policy	|通过白名单控制资源加载，防止恶意脚本执行|	设置严格的 Content-Security-Policy 响应头，限制 JS、CSS、图片等资源来源|

CSRF 攻击的两个必要条件：
- 浏览器自动携带 Cookie 跨域请求：这是浏览器的设计特性，无法避免，但可通过 SameSite 等属性限制。
    - 浏览器的 同源策略 限制 JS 跨域读数据（如无法用 JS 读取其他网站的 Cookie），但 不限制跨域发送请求（如表单提交、图片加载）
- 目标网站未验证请求来源或用户操作意图：例如，未要求用户手动确认、未添加 CSRF Token 等防护措施

防御方法：
- SameSite Cookie
- CSRF Token: `req.session.csrfToken`
    - CSRF Token：是用于防范跨站请求伪造攻击的令牌。在用户进行敏感操作（如转账、修改密码等）时，服务器会生成一个随机的 CSRF Token 并返回给客户端，客户端在后续请求中携带该 Token，服务器通过验证 Token 的有效性来判断请求是否为用户的合法操作，防止攻击者利用用户已登录的状态伪造请求。
- Referer 验证: `req.headers.origin`
